# Three-path TODO application E2E — controlled agent/operator trial

2026-10-15. Follow-up to [the intake field test](todo-three-paths-field-test.md). This is an **executed functional E2E**, not a claim that SYNTH independently generated or certified the applications. The three original workspaces and full command/result JSON are in `/home/user/todo-e2e-study/` (outside this checkout); [final application sources and tests](todo-e2e-samples/) are copied here for inspection. These are **final-state samples**, not fresh onboarding inputs. SYNTH's generated `.synth/` state and documentation projections are not included in the committed samples; the untouched source-only `knowledge/` inputs plus the later synthetic decision are included.

## Trial boundary and human/agent responsibilities

The initial greenfield workspace was empty; brownfield was an existing root-level Node ESM in-memory TODO module with add/list/complete exports and one test; documentation-only had `knowledge/product.md` (CRUD plus persistence) and `knowledge/constraints.md` (local-only versus cross-device sync conflict), with no application code. None had a Git repository or remote. Commands ran against this checkout's built `dist/cli/entry.js` from inside each isolated workspace.

The phrase “Build a TODO app” does not authorize product scope. To make a controlled trial possible, **I acted as a simulated test operator, not the actual product owner**, choosing a single-user offline Node >=20 CLI, JSON persistence, add/list/edit/done/delete, stable IDs, safe input errors, and explicitly **deferring cross-device sync**. Full [synthetic decision record](todo-e2e-samples/TEST-OPERATOR-DECISION.md). These choices were subsequently passed as synthetic answers to first-contact or written by the agent to documentation; they are **not evidence of real human approval**. The agent designed and wrote all application code, tests, package scripts and READMEs, and deliberately reused one implementation across the three paths so their functional contract is comparable. No application source was generated by SYNTH.

## Functional E2E results (agent implementation)

Each of the **three separate application directories** ran `npm test` successfully: greenfield **4/4**, brownfield **5/5** including the old API contract, documentation **4/4**. Tests fork a fresh Node process for each CLI command and verify create → list → edit → done → list → delete → list, persistence across process restarts, IDs not reused after deletion, no writes on bad input, and refusal to overwrite corrupt JSON. A second independent smoke run in each workspace executed add/edit/done/list/delete successfully, with the list process reading `{id:1,title:"Take out recycling",done:true}` from the file. The `TODO_DATA_FILE` environment variable isolates each run. The final sources under [greenfield](todo-e2e-samples/greenfield/), [brownfield](todo-e2e-samples/brownfield/) and [documentation](todo-e2e-samples/documentation/) can be independently checked with `cd <sample> && npm test` (Node >=20). They use no external npm dependencies. CLI output is JSON; failures exit nonzero. The storage uses temporary-file/rename writes, but does **not** implement concurrent-writer locking, sync, accounts or production certification.

`node dist/cli/entry.js govern --json` returned `GovernResult {delegated:true, condition:"delegated", exitCode:0}` for all three, **because the agent added each project's `govern` script as `npm test`**. Thus this only confirms delegated application tests, not independent SYNTH certification. `validate --dry-run --json` returned `ValidationPlan` with `files:[]`, `run:[]` and “No changed files detected” in all three: the disposable workspaces had no Git history. Do not count its `confidence:1` as validation of the changes. Final SYNTH `verify --json`: greenfield 5/6 Drift fail; brownfield 6/6 pass while Mission approval remained blocked; documentation 5/6 Drift fail. `doctor --json` reported healthy in all three despite those lifecycle limitations.

## Assessment

**Functional goal demonstrated; governed handoff NOT demonstrated.** With a simulated human making explicit choices, an agent can carry each intake to a runnable, tested offline TODO app. The SYNTH CLI helped capture questions, project an architecture, discover brownfield code and project documentation, but it did not write the app, resolve the contradictory requirement, recognize a completed implementation, or deliver a certified TODO change. A real user approval and a Git-backed repository/remote would be necessary to test delivery/PRs; they were intentionally not fabricated here. The Next.js-chatbot choice after Node-CLI projection, Drift after first-contact materialization, and the unrelated alignment shortcut are particularly relevant to the intended human–agent product workflow.

This report and the committed sample sources are the evidence available on the PR; detailed stdout/stderr and `.synth` artifacts remain in the disposable study directories for local inspection. No hand-editing of event streams or canonical state, no drift bypass, and no bogus alignment contract were used.
