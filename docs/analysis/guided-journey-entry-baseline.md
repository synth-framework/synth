## Small repair in this branch: source handoff, not source understanding

`first-contact --dry-run` (and the non-applying preview) now includes `sourceHandoff`: a bounded, sorted inventory of supported files under `docs/`, `knowledge/`, `src/` and `tests/`, plus root `package.json`; source-specific commands include `discover . --export` for existing code and an explicit `--knowledge-base ./knowledge` for knowledge files. Two populated document roots require an operator source selection; an empty `docs/` does not masquerade as a source. The preview's primary next step now points to source inspection (or a source-selection prompt), **not** to applying the governance plan before reading the inputs. The field says `sourceStatus: not-ingested` and explicitly warns that contents, contradictions and choices have **not** been reviewed. It does not parse arbitrary dropped files, make a design decision, run `docs generate`, change the existing approval route, or write governance state on dry-run. It caps traversal to 24 files per root and reports truncation rather than claiming completeness.

The two new regression cases were **red before** the implementation (`sourceHandoff` absent) and now pass. The ordinary `first-contact-onboard` test run also exposed a stale assertion expecting the legacy monolithic `event-log.jsonl`; it now inspects the actual partitioned event stream. A later pre-existing symlink/global-install test in that suite still returns empty stdout and fails JSON parsing; this source-preview change does not touch the CLI entrypoint or claim to fix that separate loader issue. The broader `first-contact-cli.test.js` also fails later on a legacy monolithic `event-log.jsonl` read, after its entry/start/clarify/project cases pass. Report both as red immediate-blast-radius checks, not a guided-journey pass.

## Follow-up slice: live source quotes in the handoff

The new `tests/guided-source-excerpts.test.js` was red against the path-only preview (`excerpts` absent) before implementation. It is now registered as `test:guided-source-excerpts` in the ordinary `test:all` task chain, not left as an unowned test. Its isolated workspaces cover an empty path, root-level renderer and test, competing `docs/` and `knowledge/` statements, an unsupported document, binary content with a Markdown extension, a symlink pointing outside the workspace, and an oversized source. No private or real pilot sources are in the fixture.

`first-contact --dry-run` now quotes bounded, numbered **live file prefixes** (up to eight files, 4 KiB and twelve lines per file, with long lines clipped), with a truncation marker, explicit unsupported/symlink/read warnings, and a warning when a documentation root has no supported input. Read-only `first-contact clarify` shows the same live evidence with `sourceReviewStatus: unreviewed`; when both document roots contain sources its next step asks for an explicit source selection. The preview does not change the draft, rewrite source files, read symlink targets, or write governance state. Its `sourceStatus: not-ingested` means that quoting text is **not** extracting requirements, comparing contradictions, or establishing a choice. Excerpts are live, not pinned to a revision; stale or partial evidence must not be treated as an approved brief.

**Still red:** this slice does not classify the semantic conflict between local-only and cloud-sync, ask a grounded trade-off question, record a human resolution or deferral, or link a versioned brief/plan to verified source lines. Existing `canApprove` checks only structured draft fields, and the existing `approve` route does not yet account for source review; `clarify` labels that limitation but is **not** a protection against premature approval. Do not present it as a three-path journey or an authorization gate. The older onboarding suite's symlinked-bin test and broader first-contact suite's monolithic-log assertion remain separately red as described above.
