## Follow-up slice: review the agent choice at the normal pre-merge point

The synthetic `tests/guided-choice-review.test.js` is registered as `test:guided-choice-review` and in `test:all`. Given an existing `--agent-choice` ID, `first-contact clarify --review-choice <id> --impact trivial|material --reason <why>` appends an explicit assessment to the first-contact draft and transcript. Trivial records have disposition `recorded-agent-choice`, not a fabricated human selection. For material impact the CLI requires `--decision keep|change|defer --human-response <text>` and preserves the supplied text. A later assessment supersedes the earlier one in the status review packet without deleting either record. Invalid incomplete material calls write nothing. A new `start` retains choices and their reviews (including their original intent), rather than silently losing the trail. There is **no automatic triviality threshold**; the reason is a caller's assessment, not independently validated impact. A `change` or `defer` record does not automatically alter the implementation or a working brief.

`first-contact status` now includes a choice packet with latest assessments and a `needsImpactAssessment` or `needsHumanConfirmation` indicator. `status --pr <number>` *optionally* reads local Git and `gh pr view`: `verified-head` requires a GitHub `origin`, an open PR in that same repository with the requested number, and exact local branch and HEAD SHA match. Missing/unavailable data or mismatch is shown explicitly. It neither opens a PR nor checks for reviewer approval; it does not merge, authorize lifecycle actions or gate ordinary Git operations. The CLI **cannot authenticate the caller**: even a material record's `human-response-supplied-unverified` means only that those words were supplied through a CLI flag. A matching PR head establishes review context, **not** that a human read, endorsed or kept a decision. A human should actually discuss consequential choices in the ordinary PR review before merge; this packet cannot certify that happened.

**Still red:** no trusted binding from an actual human PR review/comment to the specific keep/change/defer record, no source/offer/answer/brief/check revision trail, and no real PR or owner pilot in this branch. It reads the PR body and replaces only its own `<!-- synth:agent-choices:start -->` / `<!-- synth:agent-choices:end -->` block, or appends that block if absent; it refuses malformed/duplicate markers, rechecks the head, uses a body file rather than shell interpolation, checks the result and is idempotent. Only explicit `SYNTH choice <id>: keep|change|defer` lines in a submitted review body are listed, with GitHub account, review state, URL and reviewed commit. A generic PR approval, an unrelated comment, a pending/dismissed review or a CLI-provided `--human-response` does not become a choice decision. An old-commit review remains visible as `earlier-head`. This is **account-attributed evidence, not authenticated human consent or an authorization check**; the CLI does not know who is empowered to decide, does not infer approval from a single comment, does not mutate the draft from a review, and does not gate Git. A PR body remains editable and cannot prove which wording a reviewer saw. ## Follow-up slice: one documentation-led source-to-offer-to-provisional-brief trace
