# Bounded synthetic three-path comparison — protocol and observations

**Protocol frozen before running treatments; evidence and outcomes appended below.** This is an engineering diagnostic for proposed Expedition 1 E4, not the separately authorized owner SVG pilot, application delivery, a human choice, or a SYNTH runtime record. All files are synthetic and unbranded.

## Protocol (pre-run)

- Generate matched, fresh `plain/<fixture>` and `guided/<fixture>` directories with `node scripts/guided-three-path-comparison-fixtures.mjs <absolute empty temp root>`. The script prints SHA-256 of sorted source-path/content pairs for each fixture. It does not supply a finished offer.
- The *same live Arena.ai agent session* writes both treatments, with access to the same shell/filesystem tools and same source inputs. For plain, do not call SYNTH; use normal shell inspection, run an application baseline if present, then write a concise one-question offer (attributed input, observed facts, alternatives/trade-offs, acceptance example, unresolved choices). For guided, use the installed local build's `first-contact --dry-run`, `start`, `clarify --source-offer`, and `status`, with an agent-authored offer. **Run plain first**, then guided. This is a serial, unblinded within-session comparison; tool *availability* is equal, allowed workflow differs. Neither agent output is a real human answer. The model's exact build cannot be independently verified from this environment, and prior project context may carry over. These facts limit any causal inference.
- Initial prompt per fixture (identical words for both treatments):
  - `green`: “Build a small editable specimen-board exporter; board input and editing interaction are undecided.” No starting files.
  - `brown`: “Keep the working synthetic label renderer. Propose the smallest next slice for selectable fill color, without replacing the existing behavior. Inspect actual source and run its application test first.”
  - `docs`: “Use the supplied docs/ requirements for a small board exporter. Ask about the next editing slice before committing to an interaction style.”
  - `knowledge`: “Use the supplied knowledge/ requirements for a small board exporter. Ask about the next editing slice before committing to an interaction style.”
  - `conflict`: “Use the supplied documents for a small board exporter; do not decide between contradictory distribution requirements without asking.”
- Stop at a proposed offer. No answer, implementation delta, new application feature test, PR/CI simulation, or owner-input handoff. A CLI output without an agent-written relevant question does *not* count as a contextual offer. Workspaces may receive only treatment-specific agent output / first-contact draft after their initial hash is recorded.
- Per treatment/fixture report: command and exit, initial revision, relevant output or extracted fact, resulting agent question and alternatives, grounding, unsupported assumptions, unresolved choice, outcome `pass`/`fail`/`blocked`/`not-run`. Count agent shell commands and actual human/operator interventions separately; a scripted prompt is not an actual human intervention. A synthetic app test is separate from SYNTH tests and CLI offer validation. `pass` means only that the bounded offer rubric was observed, never owner value or delivered app.
- Rubric: preserve original input, cite the files/lines actually inspected where present, give one consequential context-specific question and two trade-off-bearing alternatives, avoid unsupported owner decisions or invented repository facts, keep one unresolved decision open. In brownfield, report the app test command/exit and propose an additive delta. For docs/knowledge, explicit source root and any conflict must remain visible. Compare grounding/provenance, question quality, unsupported assumptions, unresolved choices and operator/agent effort; if plain does equally well at lower effort, prefer simplifying the guided default rather than adding governance.

**Comparison / effort.** The actual questions, alternatives and acceptance examples were deliberately held the same across treatments (written by the same agent plain first; compare both offer artifacts), so **no measured question-quality or semantic-grounding advantage** belongs to SYNTH. Both conditions had an attributed original prompt, inspected facts where available, no unsupported factual claim about an owner answer or working feature, and one unresolved consequential decision per fixture. The guided CLI additionally checked quote/path/file identity and recorded source hashes, a versioned offer, source freshness, pending response and the `knowledge/` route; the plain agent manually checked quotes but had no automated freshness/version projection. Those are mechanical provenance gains, not proof that a proposed option is semantically good or that the user saw it. No deliberately stale source was introduced in this matched run; the separate acceptance test covers that behavior.

The agent performed one file-inspection shell operation and one offer-write operation per plain fixture (plus `npm test` for brown); the guided condition required four CLI invocations and one offer-file-write operation per fixture (plus `npm test` for brown). Grouped shell loops and authoring time were not timed; these counts are invocation categories, **not a reliable time comparison**. Both received one scripted initial prompt; actual human/operator follow-up interventions were **0** in both, with **one unresolved human decision** in each result. No actual operator response, effort in minutes, usability judgment or reviewer comprehension was measured.

**Validity and recommendation.** Same live agent session and shell/file-tool availability, matched source revisions and identical prompt text; *not independent or blinded*, and plain was authored first with this agent already familiar with SYNTH. Exact underlying model build is not independently exposed here; model matching is therefore **unverified rather than certified**. The serial design and reused wording prevent a causal improvement claim. All ten bounded offer cells passed the limited rubric, but the plain agent matched the substantive question/grounding with fewer workflow steps. **Simplify/adapt input:** retain the small opt-in citation/freshness/pending projection where traceability is valuable; do not expand default ceremony on the strength of this diagnostic. A true matched independent-agent evaluation, operator effort and the owner-authorized private SVG pilot remain future work; no application delivery or owner-value claim follows from this result.
