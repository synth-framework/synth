## Proposed Intent (Mission-level meaning for owner review)

- **Problem and audience:** an operator with a coding agent may bring only an ambiguous idea, an existing project at the working-directory root, or project material in `docs/` or `knowledge/`. Current entry surfaces offer partial source visibility but do not consistently carry source-grounded consequential choices into a scoped brief and aligned plan (S2, S3, S6). The intended users are the operator and agent; the separate owner-run SVG-board pilot is *later*, not evidence for this proposal (S3, S5).
- **Desired outcome:** SYNTH helps them inspect actual evidence, ask relevant questions and compare options, keep original human input separate from agent interpretations and provisional choices, agree only enough for the **next revisable slice**, and connect that brief to a coherent plan and checks. The agent may continue on reversible choices while keeping reasons open for ordinary pre-merge review (S1, S2, S4). This is guidance and traceability, **not** a technical guarantee that an arbitrary agent cannot act without authorization (S2, S4).
- **Explicit objectives:** (I1) evidence and its limits are visible for all three starts (S2, S3, S6); (I2) consequential options/trade-offs refer to the actual idea or inspected files rather than generic fields or invented consent (S2, S3, S5); (I3) responses, deferred questions and provisional agent choices remain distinguishable through a revision-tied brief/plan/check loop (S2, S4); (I4) an eventual separately authorized owner-run SVG-board pilot compares this guided path with an ordinary agent + concise spec + Git/CI control and informs a keep/simplify/replace decision (S1, S3, S5). I3 and I4 are **Mission horizons**, not claims that Expedition 1 implements the full loop or conducts the pilot.
- **Non-goals / forbidden interpretations:** no general-purpose app-code generator, automatic architecture choice from a generic template, fabricated human review, frozen upfront specification, new universal pre-execution lock, second Git promotion ritual, or prescriptive SVG editor/GUI/schema (S2–S5). A file list, quoted prefix, JSON output, replay pass or delegated test is not, by itself, source understanding, agreement or validated application behavior (S3, S6).

### Path-specific acceptance proposed for Expedition 1

These are **future red-to-green tests**, not behavior proven by this PR. The existing source-offer validator accepts Markdown citations only under `docs/` or `knowledge/`; it cannot presently express greenfield input or cite application code/tests. Do not satisfy this matrix by asserting those paths already work.

| Start | Fixture and required observable offer | Negative/coverage check |
| --- | --- | --- |
| **Greenfield** | Empty workspace + supplied ambiguous idea. Preserve the idea as attributed operator input; present a consequential question and alternatives with trade-offs grounded in that idea, **without inventing a file citation**. | No invented repository files, tests, platform or owner answer; source-less request is not an unsupported-file error. |
| **Brownfield** | Root-level **runnable synthetic application with real executable tests** and a documented/observable limitation. Inspect and cite existing capabilities, behavior and test results as available; offer only a bounded delta that preserves demonstrated working behavior. | A comment-only “test” is insufficient. Include a root-project layout outside the preview's `src/`, `tests/`, `docs/`, `knowledge/` + `package.json` conventions: report partial/unsupported inspection and hand off to broader discovery rather than calling it empty or claiming the app is understood. No wholesale rewrite by default. |
| **Documentation-led** | Separate docs-only and knowledge-only source workspaces; the latter must show explicit `knowledge/` routing. A further synthetic conflicting-source case offers alternatives and consequences without selecting a side. | Each variant reports the actual files read and unsupported/missing/truncated inputs; combined roots must not replace the separate variants. No inference that a file count, quotation or projection resolves the conflict. |

**Across all starts:** keep supplied input, inspected fact, agent inference, offer and any answer distinct. Validate file paths/lines/content identity where files exist; that is mechanical provenance, **not semantic validation**. A generic question relabelled “contextual,” fabricated consent or assertion that a full brief/plan is aligned fails this slice (S2, S3, S5, S6).

**First-slice acceptance:** run these path-specific red-to-green isolated fixtures and report failures and limits honestly. The synthetic plain-agent control is specified for comparison, not a substitute for a separately authorized owner pilot. No owner SVG pilot, hard-coded application architecture, retroactive runtime Expedition, or claim that full response-to-brief agreement already works (S3, S5, S6).
