## Proposed Intent (Mission-level meaning for owner review)

- **Problem and audience:** an operator with a coding agent may bring only an ambiguous idea, an existing project at the working-directory root, or project material in `docs/` or `knowledge/`. Current entry surfaces offer partial source visibility but do not consistently carry source-grounded consequential choices into a scoped brief and aligned plan (S2, S3, S6). The intended users are the operator and agent; the separate owner-run SVG-board pilot is *later*, not evidence for this proposal (S3, S5).
- **Desired outcome:** SYNTH helps them inspect actual evidence, ask relevant questions and compare options, keep original human input separate from agent interpretations and provisional choices, agree only enough for the **next revisable slice**, and connect that brief to a coherent plan and checks. The agent may continue on reversible choices while keeping reasons open for ordinary pre-merge review (S1, S2, S4). This is guidance and traceability, **not** a technical guarantee that an arbitrary agent cannot act without authorization (S2, S4).
- **Explicit objectives:** (I1) evidence and its limits are visible for all three starts (S2, S3, S6); (I2) consequential options/trade-offs cite actual inputs rather than generic fields or invented consent (S2, S3, S5); (I3) responses, deferred questions and provisional agent choices remain distinguishable through a revision-tied brief/plan/check loop (S2, S4). I3 is the **Mission horizon**, not a claim that Expedition 1 implements the entire loop.
- **Non-goals / forbidden interpretations:** no general-purpose app-code generator, automatic architecture choice from a generic template, fabricated human review, frozen upfront specification, new universal pre-execution lock, second Git promotion ritual, or prescriptive SVG editor/GUI/schema (S2–S5). A file list, quoted prefix, JSON output, replay pass or delegated test is not, by itself, source understanding, agreement or validated application behavior (S3, S6).
