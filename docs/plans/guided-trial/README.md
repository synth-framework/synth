# Guided-journey trial — instruction set

This directory holds the instructions a running agent reads inside its workspace, plus the index for the operator. The full protocol, setup command, compliance checklist and limits live in [the trial instructions](../guided-installed-cli-trial-instructions.md). Nothing here starts a cell, and nothing here is trial evidence.

## The files

| File | Read by | Purpose |
| --- | --- | --- |
| `instructions/guided.md` | The agent in a **guided** cell | Starts with the SYNTH initialization process, then the tests, offer requirements, honesty rules and report shape |
| `instructions/plain.md` | The agent in a **plain** cell | Same tests, observations, rules and report shape, with no prescribed starting process |
| `README.md` (this file) | The operator | What the tests are, how a cell is handed off, and how the set is kept consistent |

Setup stages the condition-appropriate instruction set into each workspace as `INSTRUCTIONS.md` and writes a short handoff note naming the case and the workspace. The instruction set is staged, not generated by the setup script: the only script-written text is the handoff note's case, path and CLI location.

## The tests

All five tests are listed in full inside each instruction set, so the agent sees the whole set and its own assignment. Three are required; two are optional extras for a longer time box.

| Test | Case id | Starting workspace | Required observation |
| --- | --- | --- | --- |
| Greenfield | `green` | Empty workspace, task text only | Relevant questions about board kind, inputs, editing, validation; no invented GUI/stack; no automatic approval |
| Brownfield | `brown` | Small working synthetic SVG-board renderer with a test and a documented limitation | Existing behavior, test and limitation cited; only the delta proposed; no wholesale rewrite |
| Documentation-led | `docs` | Source-only `docs/requirements.md` | Files read and cited by path and line; nothing silently resolved |
| Knowledge-rooted (optional) | `knowledge` | Source-only `knowledge/requirements.md` | Same as documentation-led, from the non-conventional root |
| Conflicting documents (optional) | `conflict` | `docs/scope.md` versus `knowledge/scope.md` | Both cited; contradiction surfaced as an unresolved decision |

Task text and fixture bytes are single-sourced in `scripts/lib/guided-trial-fixtures.mjs`; `npm run test:guided-installed-trial-setup` fails if the task text quoted in these instruction sets ever diverges from that file, or if fixtures drift from the published revisions.

## Handing off one cell

1. Open one fresh agent session per cell. Never reuse a session between a guided and a plain cell.
2. Paste the handoff note for that cell (written by setup): `kickoff/guided-<case>.md` in the trial root, or `kickoff-<case>.md` in the plain root.
3. The agent reads `INSTRUCTIONS.md` in its workspace and follows it. In a guided cell its first act is the SYNTH initialization process; in a plain cell there is no prescribed first command.
4. Log verbatim any help you give beyond pasting the note.

## Keeping the two sets consistent

The two instruction sets must differ **only** in the condition they describe: the guided set names the tool and its initialization process, and the plain set must not. Both carry the same test table, the same required observations, the same honesty rules and the same report shape. When editing either file, check the other, then run:

```bash
npm run test:guided-installed-trial-setup
```

That test also enforces the hard rule that the plain set never contains the tool's name or its commands.
