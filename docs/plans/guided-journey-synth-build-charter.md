## Goal and product boundary

Restore one **guided human–agent path from evidence to agreed build brief and aligned plan** for (a) an idea in an empty directory, (b) a repository at the working-directory root, and (c) documents under `docs/` or `knowledge/`. The agent may inspect sources, reason and write the eventual application; SYNTH should make the handoff, decisions, options, provenance and next steps visible and consistent. The first product promise is **guidance and traceability**, not a new technical guarantee that an agent cannot work without approval. Existing safety checks remain; an unresolved material conflict must not be labelled an agreed choice. No new public verb or second PR-promotion ritual by default.

## Implementation slices and exit evidence

1. **Entry evidence and source handoff.** Preserve the existing greenfield idea path; for brownfield, make `discover . --export` evidence available to the agent/first-contact handoff so it names existing capabilities and gaps rather than recommending a generic rewrite; for knowledge-fed input, ensure the operator knows `docs generate` defaults to `./docs` and `knowledge/` needs explicit `--knowledge-base ./knowledge` unless routing is repaired with a proven source selection. Show actual scanned paths/counts and source excerpts/references. Never treat seven generic projections as proof the intended docs were read. Agree on what an agent-authored synopsis contributes versus what SYNTH itself checks. **Exit:** all three paths identify their actual input and its provenance; absent intended sources produce an actionable warning.
2. **Contextual clarification and human decision record.** From each path, show a small set of consequential unknowns, grounded alternatives and trade-offs rather than only fixed audience/runtime/language fields. Distinguish source fact, agent inference, option, explicitly authorized default, human choice and deferred question. For the documentation fixture, conflicting local-only versus sync statements remain open until a simulated human **explicitly** chooses; for the SVG pilot, web versus desktop and vague layout rules remain proposals until the owner chooses. Do not forge a reviewer via `alignment prepare` or turn the owner's private reference SVGs into public source files. **Exit:** a versioned, reviewable build brief links each required behavior and architecture constraint to its source/decision; an unresolved material choice is visibly not agreed. Keep agent-specific intelligence optional and the handoff agent-agnostic.
3. **Aligned plan and materialization.** Project architecture, adapters and workflow from the **same** agreed brief. If there is no suitable template, use an honestly labelled generic bounded plan or ask; do not choose a Next.js chatbot after a Node CLI projection. The Mission purpose, planned work and suggested application checks must relate to the requested behavior. The agent may generate application code later; SYNTH must not claim to have done so. Materialization must leave replay **and** `verify` consistent without hand-edited event streams/canonical state. **Exit:** three path-specific, testable briefs and coherent previews/materialized artifacts; the wrong-template and 0-versus-4 event-offset cases fail the regression harness if reintroduced.
4. **Truthful execution handoff.** Surface the agreed brief and evidence requirements to a separate implementing agent, including which checks were actually run and what remains unanswered. On a Git-backed pilot, distinguish local choice, reviewable branch and published `main` without assuming cross-branch propagation. With no Git history, `validate` must not claim actual code-change validation merely because it returns confidence 1; delegated `govern: npm test` must be labelled an application test, not independent SYNTH certification. Use ordinary PR review/integration; coordinate with LIFE-002 rather than implementing another governing branch or lifecycle ceremony. **Exit:** status and proof link to exact scope/revision/check results or explicitly say unavailable; a reviewer cannot mistake an unrun check for a pass.
