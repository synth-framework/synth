# Guided journey: independent workflow proposal vs. SYNTH today

**Status (2026-10-15): proposal for owner discussion, not an approved product contract, runtime Mission/Expedition, implementation authorization, or pilot result.** Comparison based on the independent human–agent workflow described in this conversation, *then* checked against this branch at `710139bcc6d6`. The proposal is deliberately not derived from the current command hierarchy. Keep the previously accepted [build](guided-journey-synth-build-charter.md) and [test](guided-journey-test-charter.md) review scopes as separate references; this document may prompt their revision **after** discussion, not silently replace them.

## 1. The workflow I would want as a coding agent

1. **Orient:** capture the person's original request verbatim; inspect the actual idea, documents, code and tests. Report observed facts with references, interpretations as proposals, and unknowns as unknowns. Preserve working behaviour in an existing project. An empty idea needs no invented repository facts.
2. **Clarify consequential choices:** ask a small, contextual batch, each with why it matters, options, consequences, and a recommendation *when justified*. The person can choose, explicitly delegate a bounded decision, or defer it. The agent handles cheap/reversible details; a substantive conflict stays open until reviewed. An exploratory prototype can answer a question but is not an agreed deliverable.
3. **Agree on a proportional brief:** a few paragraphs for a small change or a versioned document for larger work: outcome, users, first slice, non-goals, confirmed decisions, constraints, unresolved questions, and observable acceptance examples. The agent drafts; the person confirms the *meaning* of consequential commitments, not every command.
4. **Plan and implement a thin slice:** preserve existing capabilities, state expected changes and checks, write application code with ordinary tools, and pause before irreversible/costly/sensitive acts. If new evidence contradicts the brief, propose a revision rather than quietly reinterpreting it. Use normal Git/PR/CI, not a second publication ceremony.
5. **Compare outcome to agreement:** demonstrate user scenarios and distinguish checks actually run (with revision/result) from delegated, failed, unavailable and not-run checks. Surface deviations and outstanding decisions at handoff; iterate at the earliest invalid assumption.

The companion CLI's job would be **durable project memory plus a small, current context packet** for the agent and person—not a 1,000-line instruction file and not an assertion that it controls everything an arbitrary agent does. The packet should identify its branch/revision, goal, relevant evidence, confirmed choices, open decisions, current brief, checks and most useful next question/action; detailed records remain queryable by ID. A tiny generated agent bootstrap or tool integration could instruct the agent to consult it at session start, after meaningful scope/branch changes and before claiming completion. The agent still inspects sources and reasons; the CLI records typed facts and checks mechanical consistency; the human owns consequential choices.

### Determinism and drift contract

**Make commitments deterministic, not model prose.** Preserve separately (a) exact original human request, (b) the *exact offer displayed*—question, option texts, trade-offs, recommendation and version—(c) the original human answer and its provenance, and (d) the resulting choice, bounded delegation or deferral. An agent interpretation of an ambiguous answer remains a proposal. An edited offer or revised decision supersedes, rather than silently overwrites, what was previously shown. Link claims to source paths/line ranges plus file content identity and, when available, repository revision; changes make dependent claims *stale for review*, not retroactively false or automatically reapproved. A reproducible brief is a projection of confirmed commitments; AI-authored wording can vary before confirmation.

Reduce drift with a compact, revision-pinned context at session restart and a stated intended delta before work. Detect it with explicit trace links from source/decision to brief, plan, changed behaviour and acceptance examples. Contain it with small demonstrations, human review of consequential deviations and checks tied to the actual code revision. Only mechanically supportable claims (e.g. recorded option version, intact source reference, executed check and its exit status) are mechanically certified. Semantic agreement and code correctness cannot be guaranteed by a CLI; an agent can act outside it. Do **not** turn this into a blanket pre-execution lock or a false identity/approval guarantee. For meaningful human attribution, a trusted UI/channel or confirmation of the proposed decision record is needed; an agent-supplied `actor: human` label alone is not evidence.

## 4. Questions for our review (proposed defaults, not settled decisions)

1. **What must be confirmed by you?** Proposed default: consequential product commitments and irreversible/sensitive acts; routine reversible implementation choices may be delegated, while material contradictions remain open. Would you draw that line elsewhere?
2. **What exactly does “agreed” mean?** Proposed default: a short brief whose consequential statements refer to the exact offer, your original response or explicit delegation, and supporting sources; unknowns may remain if clearly scoped out of the first slice. A generic field-completion score alone is insufficient.
3. **How should a CLI recognize your response?** Proposed default: preserve raw text and the displayed offer; if the only channel is an agent relaying your words, require explicit confirmation before attributing a consequential choice to you. Do not claim cryptographic identity from a role string.
4. **How much agent-facing instruction is acceptable?** Proposed default: tiny generated bootstrap plus a typed, compact context packet from existing read surfaces; any migration from the current generated `AGENTS.md` needs evidence that safety requirements survive and agents actually retrieve the packet.
5. **What would disprove the proposal?** Proposed default: matched pilot shows no better decisions or fewer mistakes than an agent + concise spec, but adds more operator work; simplify instead of layering more ceremonies.

**Boundary:** This is a review and comparison artifact only. No command or design name in this document creates/approves a Mission or Expedition, runs the owner's SVG pilot, records a human choice, changes a guard, or settles the separate delivery/seal lifecycle. Do not treat the proposed defaults above as answers from the owner.
